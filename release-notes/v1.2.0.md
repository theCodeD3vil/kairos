# Kairos v1.2.0

## Highlights

- **Fresh editor integration.** Kairos now tracks coding activity from [Fresh](https://getfresh.dev), the terminal IDE. Install the plugin from Kairos Desktop Settings → Editor Integrations → Fresh → Install Plugin. No Node.js required.
- **Multi-editor status UI.** Settings and overview pages now show VS Code and Fresh as separate panels with per-editor health badges, sync times, and event timestamps.
- Real-time UI updates — data refreshes live as events arrive from any connected editor.

## Fresh Integration

- `kairos-fresh-bridge` — a standalone Go helper that manages desktop discovery, WebSocket auth, offline event queuing, and reconnect with exponential backoff. Ships as a universal macOS binary (arm64 + amd64) and separate Linux amd64/arm64 binaries in the release artifacts.
- Fresh plugin (`kairos.ts`) — a single-file TypeScript plugin with no external dependencies. Tracks buffer saves, edits, file opens, and 30-second heartbeats. Installed to `~/.config/fresh/plugins/` by Kairos Desktop.
- **One-click install.** Settings → Editor Integrations → Fresh → Install Plugin copies the bridge binary to `/usr/local/bin/` (with elevation prompt on macOS) and the plugin to the Fresh plugins directory.
- **Auto-update.** On each Kairos Desktop launch, the installed plugin is silently updated if its embedded `@kairos-version` marker is older than the bundled version.
- Bridge binary is codesigned as part of the macOS app bundle — no Gatekeeper prompts.
- Offline queue: events recorded when Kairos Desktop is unreachable are replayed on next connection.

## Desktop

- Editor Integrations section in Settings replaces the VS Code-only panel. Both editors show version, last sync, last event, and connection state.
- Fresh status badge shows **Active** (green) when an event was received within the last 5 minutes, even though the bridge disconnects after each send.
- Refresh Status button now works for any editor, not just VS Code.
- `CheckFreshInstallation` and `InstallFreshPlugin` Wails bindings exposed to frontend.

## Infrastructure

- `make fresh-plugin-sync` — syncs plugin source into the Go embed location. Required before any `go build`. All relevant Makefile targets depend on it.
- `make fresh-bridge-build` — compiles the bridge binary and updates embed source.
- `make fresh-bridge-bundle-app` — injects bridge binary and plugin into a built `.app` bundle before signing.
- CI: cross-compilation step added to `desktop-release.yml`. Standalone bridge binaries and the plugin `.ts` file are included as release artifacts.

## Tests

- 12 new Go tests: bridge discovery ordering, loopback validation, offline queue drain/enqueue/re-enqueue, identity create/load idempotency.
- 9 new frontend tests: `adaptEditorIntegrationStatuses`, `editorDisplayName`, badge recency logic.
- Full suite green (191 Go tests, 89 frontend tests).
