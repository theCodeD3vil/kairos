# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repo layout

Monorepo combining pnpm workspaces with a Go module:

- `apps/desktop` — Wails app. Go backend (`main.go`, `app.go`, `internal/`) embeds the React build under `frontend/dist`. Frontend lives in `apps/desktop/frontend` and is a pnpm workspace.
- `apps/vscode-extension` — VS Code extension (`kairos-vscode`), esbuild-bundled, talks to desktop over WebSocket.
- `packages/shared` (`@kairos/shared`) — TS types/contracts shared between desktop frontend and extension. Subpath exports: `./domain`, `./ingestion`, `./settings`, `./views`.
- `apps/web` exists but is not a pnpm workspace member; treat it as separate from the main build graph.
- `VERSION` is the product release marker (currently `1.1.13`). Desktop build version comes from `apps/desktop/internal/buildinfo/buildinfo.go` overridden via `-ldflags` in CI; extension version is `apps/vscode-extension/package.json`. The CI step `verify-version-sync.sh` enforces alignment.

## Common commands

Use the Makefile when possible — it wires pnpm filters and Go in the right order.

```bash
make doctor                  # check go, node, pnpm, wails
make install                 # pnpm install + go mod tidy in apps/desktop
make typecheck               # pnpm typecheck across workspaces
make build                   # shared → frontend → extension → desktop go build
make format                  # prettier
```

Dev loops:

```bash
pnpm dev:desktop             # frontend only at http://localhost:5173
make desktop-dev             # full Wails dev (Go + frontend hot reload)
make dev                     # backgrounded dev (logs in .dev/), make dev-down to stop
```

Tests:

```bash
make test-unit               # frontend vitest + extension tests + go test ./...
make test-e2e                # frontend Playwright + go test -run TestE2E
make test-all
pnpm --filter @kairos/desktop-frontend test -- src/path/file.test.ts   # single vitest file
pnpm --filter @kairos/desktop-frontend test:e2e -- e2e/file.spec.ts     # single Playwright file
cd apps/desktop && go test ./internal/sessionization -run TestSplit     # single Go test
```

Release packaging:

```bash
make desktop-release-check                                              # typecheck + build + go test
make desktop-release-build                                              # wails build (needs wails CLI)
make desktop-release-artifacts KAIROS_VERSION=$(cat VERSION)            # collects into dist/release/...
pnpm --filter kairos-vscode verify:release && pnpm --filter kairos-vscode package:vsix
```

## Wails bindings

Anything bound on `App` in `apps/desktop/app.go` is exposed to the frontend through generated TS at `apps/desktop/frontend/wailsjs/go/main/App` plus types at `wailsjs/go/models.ts`. These files are generated by `wails dev`/`wails build` — do not hand-edit them. After changing a binding signature or a `contracts` struct, re-run a Wails build (or `make desktop-dev`) so the frontend imports stay in sync.

## Backend architecture (apps/desktop/internal)

- `storage/` — SQLite store. WAL mode, FK on, single open conn, transactional ingestion writes. Migrations in `storage/migrations/*.sql` are forward-only and embedded via `//go:embed`; startup aborts if any migration fails (`docs/backend-hardening.md`).
- `ingestion/` — accepts batched events from the extension. Validates `machine`/`extension`/`events`, caps batch at 500, body at 1 MiB, enforces per-field length caps from `config/limits.go`. Partial-success on partially valid batches.
- `sessionization/` — derives sessions from raw events. Deterministic order (machine, timestamp, id). Two phases: split on >5min idle gaps, then merge adjacent same-date/same-machine/same-project sessions inside `sessionMergeThresholdMinutes`. Never merges across machines or calendar dates. See `docs/sessionization.md`.
- `views/` — page-data assembly for Overview/Calendar/Sessions/Analytics/Settings. Range labels supported: `today`, `week`, `month`, `last-7-days`, `last-30-days`, `all-time`, or explicit `YYYY-MM-DD..YYYY-MM-DD`. Calendar uses `YYYY-MM` and `YYYY-MM-DD`. See `docs/page-data-assembly.md`.
- `settings/` — desktop is canonical settings authority. Sections persist as JSON rows in `settings_sections` (`general`, `privacy`, `tracking`, `exclusions`, `extension`, `appBehavior`). Effective settings = defaults overlaid with valid persisted sections plus derived runtime sections. Extension reads its filtered slice via `GetExtensionEffectiveSettings()`. See `docs/settings-system.md`.
- `server/` — local-only HTTP/WS bridge (`127.0.0.1`). Can be disabled via `KAIROS_DISABLE_LOCAL_SERVER=1`. Discovery file path overridable via `KAIROS_BRIDGE_DISCOVERY_FILE`.
- `contracts/` — DTOs serialized to the frontend through Wails; keep field tags (`json:"..."`) stable since they appear verbatim in `wailsjs/go/models.ts`.
- `transfer/`, `updates/`, `analytics/`, `buildinfo/` — import/export, GitHub-release update checks, analytics rollups, build metadata.

Local-only posture: any new ingestion handler must bind `127.0.0.1`, accept `POST` + JSON only, and stay within the existing request-size cap.

## Frontend architecture (apps/desktop/frontend)

- React 19 + Vite + Tailwind. `HashRouter` (suits the embedded asset server). Path alias `@/` → `src/`.
- Routing: `src/app/routes.tsx` lazy-loads `OverviewPage`, `AnalyticsPage`, `SessionsPage`, `CalendarPage`, `SettingsPage`. `LandingRedirect` resolves the initial page from desktop settings.
- Data access: every page goes through `src/lib/backend/page-data.ts` (and `settings.ts`), which wrap the generated Wails calls (`GetOverviewData`, `GetCalendarMonthData`, `GetCalendarDayData`, `GetSessionsPageData`, `GetSettingsData`, `ListSessionsForRange`, `ListKnownMachines`, `GetVSCodeBridgeHealth`). Do not import from `wailsjs/go/...` inside page components — there is a test (`src/app/no-mock-runtime-imports.test.ts`) guarding the boundary.
- Caching/loading: `DesktopDataProvider` + `useDesktopResource` hook keyed by `desktopResourceKeys.*`. Toasts via `src/components/toast/`, sync indicator via `trackSyncOperation` in `src/lib/sync-status.ts`.
- `src/data/mock*.ts` files are types + sample shapes for tests — runtime code should not import them as data, only as types. The guard test above enforces this.

## VS Code extension (apps/vscode-extension)

- Entry `src/extension.ts`. On activation it creates a status bar, ensures `kairos.machineId` / `kairos.installationId`, opens a local sql.js outbox DB, and spawns `KairosRuntime` (`src/runtime/`) which talks to desktop via `WebSocketDesktopClient`.
- Bundled with `esbuild.mjs`. `pnpm --filter @kairos/shared build` is a precondition (`pretest`/`pretypecheck`) so the workspace dependency resolves to `dist/`.
- Tests compile with `tsconfig.test.json` then run through `scripts/run-compiled-tests.mjs`.

## Conventions specific to this repo

- **UI headers are title-only.** No subtitle/description text under page or section headers unless the user explicitly asks (`AGENTS.md`).
- **Desktop frontend UI components come from JolyUI** (`apps/desktop/frontend/UI_COMPONENT_SOURCE.md`). Add via `pnpm dlx shadcn@latest add "https://jolyui.dev/r/<component>"`. Registry alias `@jolyui` is wired in `components.json`.
- Mock-data files exist only for tests and prototyping; never reintroduce them as runtime sources for real pages.
- Settings changes that affect ingestion/sessionization (e.g. `idleTimeoutMinutes`, `sessionMergeThresholdMinutes`, `privacy.filePathMode`, `exclusions.*`) are applied through the existing services — don't read settings directly from random spots in the backend.
